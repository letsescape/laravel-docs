이 저장소의 Translation Sync 작업을 단일 담당 에이전트로 끝까지 수행하라.
먼저 `AGENTS.md`, `.docs/system-prompt.md`, `translation-sync/docs/00-workflow-summary.md`부터 `08-error-cases.md`까지, 그리고 `docs/review/*.md`를 모두 읽고, `.docs/system-prompt.md`를 이번 작업의 실행·판정 계약으로 삼아라. (`.docs/prompt.md`는 참고 사항)

이제 이 저장소는 너 혼자 작업한다. 
다른 에이전트의 변경은 없으므로, 기존 로컬 변경·worktree·stash·ignored 산출물은 보존 대상이 아니라 판정 대상이다. 
시작할 때 전부 재고하고 각각을 현재 목표에 포함할지, 이미 의미를 잃었으니 제거할지, 근거가 부족해 보류할지 판정하라. 
판정은 브랜치 병합 이력이 아니라 현재 HEAD·worktree와의 내용 대조로 하라. 
되돌릴 수 없는 제거는 그 내용 요약과 근거를 보고에 남긴 뒤에 하라. 
단 `.docs/review/*.md`, `.docs/*.md` 재고·보고 대상일 뿐 삭제하지 마라.

모든 작업은 로컬에서만 하라. 
원격에 영향을 주는 행위, 활성 저장소의 commit·staging·push·PR, 새 worktree나 stash 생성을 하지 마라. 
검증 도구가 저장소 밖 임시 clone 안에서 만드는 commit은 예외이며, 그 이유로 `make translation-check`를 건너뛰지 마라. 
`.env`는 권한 문제로 열람할 수 없으니, `dot_env` 의 정보를 활용하여, 운영 환경과 동일하게 테스트를 진행하라.

절대 질문, 선택지 제시, 승인 요청, 중간 확인 등을 이유로, 작업을 멈추지 말고 저장소 증거와 공식 1차 자료를 바탕으로 스스로 결정하라. 
문서와 코드의 불일치를 전수 조사하고, 재현 테스트를 먼저 만든 뒤 최소한의 구현·문서 수정을 수행하라. 
시스템 프롬프트가 정의한 필수 검증을 마지막 수정 이후 다시 실행해 실제 통과 증거를 확보할 때까지 진단→수정→재검증을 반복하라.

완료 시 최종 판정, 로컬 상태 처분 내역, 변경 파일, 실행한 검증 명령과 결과, 공식 근거, 실행할 수 없었던 conditional gate만 간결하게 보고하라.
