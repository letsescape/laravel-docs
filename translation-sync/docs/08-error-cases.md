# 오류 처리 및 복구 설계

## 1. 목적

번역 동기화 워크플로우에서 발생할 수 있는 오류를 단계별로 분류하고, 각 분류에 대한 복구 정책을 규범적으로 정의한다.

## 2. 범위

이 문서는 다음 오류 분류와 복구 정책만 소유한다.

- 설정 오류
- 입력 오류
- 변경 계획 오류
- 번역 오류
- 후처리 오류
- 검증 오류
- 사이드바 오류
- 산출 오류

단계별 세부 설계는 각 단계 문서가, 전체 순서와 회귀 규칙은 [00-workflow-summary.md](00-workflow-summary.md)가 소유한다.

## 3. 입력

| 항목 | 설명 |
|------|------|
| 워크플로우 실행 상태 | 각 단계의 성공·실패 결과 |
| 오류 발생 context | 오류가 발생한 단계, locale, 문서, 블록 식별자 |

## 4. 출력

| 항목 | 설명 |
|------|------|
| 오류 분류 결과 | 오류가 속한 분류(설정/입력/계획/번역/후처리/검증/sidebar/산출) |
| 복구 동작 | 분류에 따른 중단, 재시도, 또는 실패 처리 결과 |

## 5. 불변 조건

1. 검증을 통과하지 않은 산출물을 기록해서는 안 된다.
2. 실패한 블록을 추정 번역으로 채워서는 안 된다.
3. 재시도 중 원문 diff, 전처리 결과, 플레이스홀더 매핑, 기존 locale 문서를 변경해서는 안 된다.
4. provider 호출이 완료되지 않은 상태에서 후처리를 실행해서는 안 된다.
5. 오류 분류가 결정되지 않으면 fail-closed로 처리해야 한다.

## 6. 오류 분류 및 복구 정책

### 6.1 설정 오류 (C)

번역 실행 전에 환경 설정의 유효성을 확인하는 단계에서 발생하는 오류다.

| 조건 | 복구 정책 |
|------|-----------|
| provider 환경 변수 미설정 또는 허용값 외 | 즉시 중단해야 한다. 번역 단계로 넘겨서는 안 된다. |
| provider별 필수 환경 변수 누락 | 즉시 중단해야 한다. |
| replay 전용 provider가 replay 밖에서 선택됨 | 즉시 중단해야 한다. |
| 숫자형 런타임 옵션의 형식 오류 | 즉시 중단해야 한다. |

설정 오류는 재시도 대상이 아니다. 종료 코드와 짧은 진단 메시지를 반환해야 한다.

### 6.2 입력 오류 (I)

동기화 대상 파일과 리소스의 전제 조건이 충족되지 않을 때 발생하는 오류다.

| 조건 | 복구 정책 |
|------|-----------|
| 원문 수정인데 기존 locale 번역 파일이 없음 | 해당 문서를 실패 처리해야 한다. 추정 번역을 생성해서는 안 된다. |
| 변경이 감지됐으나 diff hunk가 비어 있음 | 해당 문서를 실패 처리해야 한다. |
| locale별 번역 프롬프트 파일이 없음 | 실행 전체를 중단해야 한다. |

입력 전제가 모호하면 기록하지 않고 실패하는 fail-closed 동작을 유지해야 한다.

### 6.3 변경 계획 오류 (P)

raw 변경을 정규화된 번역 소유 단위 변경 계획으로 변환하는 단계에서 발생하는 오류다.

| 조건 | 복구 정책 |
|------|-----------|
| 블록 경계를 결정할 수 없음 | 해당 문서를 실패 처리해야 한다. |
| 삽입 위치의 컨텍스트를 찾을 수 없음 | 해당 문서를 실패 처리해야 한다. |
| 기존 문서의 구조 주석이 손상됨 | 해당 문서를 실패 처리해야 한다. |
| 번역 블록 수와 결과 수가 불일치 | 해당 문서를 실패 처리해야 한다. |

변경 계획 오류는 해당 문서 단위로 실패를 격리해야 한다. 모호한 매칭을 추정 적용해서는 안 된다.

### 6.4 번역 오류 (T)

provider에 번역을 요청하고 응답을 수신하는 단계에서 발생하는 오류다.

| 조건 | 재시도 여부 | 최대 시도 | 복구 정책 |
|------|:-----------:|:---------:|-----------|
| timeout·네트워크 오류·429·5xx | 예 | transport 3회 | 동일 입력과 동일 설정으로 재요청해야 한다. 소진 시 해당 locale target을 실패 처리해야 한다. |
| 응답 없음(빈 응답) | 예 | transport 3회 | 동일하게 재요청해야 한다. 소진 시 실패 처리해야 한다. |
| 인증 실패·비일시 4xx | 아니오 | 1회 | 즉시 해당 target을 실패 처리해야 한다. |
| CLI 명령 비정상 종료 | 아니오 | 1회 | stderr 진단과 함께 해당 target을 실패 처리해야 한다. |
| 완료 상태가 아닌 부분 응답 | 아니오 | 1회 | 부분 Markdown을 기록해서는 안 된다. 해당 target을 실패 처리해야 한다. |

블록당 완료 응답 평가는 최초 포함 최대 2회다. 각 평가의 transport는 최대 3회 시도할 수 있다. 따라서 물리 호출 상한은 블록당 6회다.

### 6.5 후처리 오류 (R)

번역 완료 블록의 Markdown·HTML 형식과 플레이스홀더를 최종화하는 단계에서 발생하는 오류다.

| 조건 | 복구 정책 |
|------|-----------|
| 플레이스홀더 원본 매핑 부재 또는 복원 불가 | 해당 target을 즉시 실패 처리하고 계획을 적용해서는 안 된다. |
| 링크·heading markup 대응이 모호함 | 유일 대응이 증명될 때만 복구하고, 그렇지 않으면 해당 target을 즉시 실패 처리해야 한다. |
| 형식 변환 뒤 잔존 패턴 발견 | 문서 검증 단계에서 실패 처리하고 기록해서는 안 된다. |

후처리가 입력을 안전하게 변환하거나 복원할 수 없으면 해당 target을 즉시 실패 처리해야 한다. 안전한 변환을 완료한 결과에 잔존 위반이 있는지는 검증 단계가 최종 판정하며, 어느 경우에도 검증 가능한 결과로 가장해서는 안 된다.

### 6.6 검증 오류 (V)

문서 구조 보존 여부를 확인하는 단계에서 발생하는 오류다.

| 분류 | 조건 | 복구 정책 |
|------|------|-----------|
| 잔존 패턴 | 치환되지 않은 플레이스홀더, legacy 마커, 미닫힌 태그 잔존 | 해당 문서를 기록해서는 안 된다. |
| 원문 대조 | 링크·인라인 코드·코드 블록·heading·앵커의 값 또는 순서 불일치 | 해당 문서를 기록해서는 안 된다. |
| 구조 주석 | 원문 주석 누락 또는 소유 관계 불일치 | 해당 문서를 기록해서는 안 된다. |
| front matter | 제목 불일치 | 해당 문서를 기록해서는 안 된다. |
| 응답 계약 위반 | 구조 verifier가 issue를 보고 | 지원되는 issue는 feedback과 함께 한 번 새 완료 응답을 요청할 수 있다. 최종 실패 시 기록해서는 안 된다. |

검증 오류가 하나라도 있는 문서는 locale 산출물로 기록해서는 안 된다. 실행을 실패로 표시해야 한다.

### 6.7 사이드바 오류 (S)

`documentation.md` 기준으로 sidebar JSON을 생성·검증하는 단계에서 발생하는 오류다.

| 조건 | 복구 정책 |
|------|-----------|
| `documentation.md`가 존재하지 않는 문서를 참조 | 실행을 실패 처리해야 한다. |
| 지원하지 않는 버전 또는 저장소 밖 경로 | 실행을 실패 처리해야 한다. |
| sidebar 항목 누락 또는 라벨 불일치 | 사이드바 갱신을 재실행해야 한다. |
| locale sidebar override JSON 잔존 | 해당 파일을 삭제해야 한다. 삭제 후에도 잔존하면 실행을 실패 처리해야 한다. |

사이드바 오류는 해당 버전 또는 실행 전체 단위로 실패를 처리해야 한다.

### 6.8 산출 오류 (A)

최종 산출물의 git 반영 기준을 확인하는 단계에서 발생하는 오류다.

| 조건 | 복구 정책 |
|------|-----------|
| 허용 경로 밖 파일 변경 | 커밋해서는 안 된다. 워크플로우를 실패로 종료해야 한다. |
| 상태 정합성 위반(EN·KO·JA 상태 불일치) | 커밋해서는 안 된다. 워크플로우를 실패로 종료해야 한다. |
| 증명되지 않은 영어 단독 수정 | 커밋해서는 안 된다. 워크플로우를 실패로 종료해야 한다. |
| locale sidebar override JSON 생성·수정 | 커밋해서는 안 된다. 워크플로우를 실패로 종료해야 한다. |

산출 오류 발생 시 어떤 변경도 원격 브랜치에 반영해서는 안 된다.

## 7. 실패 정책 공통 원칙

1. 지원하는 변경 종류를 먼저 분류하고, 처리 경로가 하나로 결정되지 않으면 추정 적용해서는 안 된다.
2. 재시도 중 원문 diff, 전처리 결과, 플레이스홀더 매핑, 기존 locale 문서를 변경해서는 안 된다.
3. 실패한 블록을 추정 번역으로 채워서는 안 된다.
4. 설정 오류는 번역 단계로 넘겨서는 안 된다.
5. provider 호출이 완료되지 않으면 후처리를 실행해서는 안 된다.
6. 검증에 실패한 문서를 기록해서는 안 된다.
7. fail-fast 정책을 선택한 실행은 첫 locale target 실패에서 이후 target과 sidebar 처리를 중단해야 한다.
8. 실행 단위 원자 publication을 제공하지 않는 운영 모드에서 부분 로컬 상태가 남으면 커밋과 push를 금지하고, 동일한 고정 원문 기준으로 복구 또는 재실행해야 한다.

## 8. 수용 기준

- 모든 오류가 정의된 분류 중 하나에 속하고, 해당 복구 정책에 따라 처리되어야 한다.
- 검증 실패 문서가 locale 산출물로 기록되어서는 안 된다.
- 재시도 상한을 초과한 블록이 실패 처리되어야 한다.
- 설정 오류 발생 시 번역 단계에 진입하지 않아야 한다.
- 산출 오류 발생 시 어떤 변경도 커밋되어서는 안 된다.
