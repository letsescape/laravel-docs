`````md
# 번역 후 정제 / 검증 작업 계획

## 1. 작업 목적

영어 기술 문서 변경분을 한국어로 반영한 뒤, 최종 문서의 형식, 코드, 링크, 이미지, 노트, 플레이스홀더가 정상적으로 유지되었는지 정제하고 검증한다.

이 단계의 목표는 다음과 같다.

- 번역 결과의 Markdown 구조를 안정화한다.
- 코드, 링크, 앵커, 인라인 코드, 이미지 등 기술 문서 요소를 보존한다.
- 문서 렌더링에 불필요하거나 문제를 일으키는 원문 스타일 요소를 제거한다.
- 다양한 노트/툴팁 표현을 문서 표준 형식으로 통일한다.
- `{{version}}` 같은 플레이스홀더를 최종 문서용 버전 문자열로 치환한다.
- 최종 문서가 원문 구조와 의미를 유지하는지 검증한다.

---

## 2. 전체 처리 흐름

정제와 검증은 다음 순서로 진행한다.

```text
1. 번역 전 사전 정제
2. 변경분 번역
3. 번역 후 후처리 정제
4. 구조 및 형식 검증
5. 링크 / 앵커 / 코드 검증
6. 최종 QA 결과 정리
```

정제 항목 중 일부는 번역 전에 처리해야 한다.

특히 다음 항목은 번역 전에 처리한다.

- base64 인코딩 이미지 플레이스홀더 치환
- `<style>` 태그 및 페이지 디자인 코드 제거
- 번역 대상이 아닌 대형 데이터 또는 렌더링 전용 코드 제거

번역 후에는 다음을 처리한다.

- base64 이미지 복원
- 들여쓰기 기반 코드 블록 정리
- `<img>` 태그 self-closing 처리
- 제목 옆 원문 스타일 클래스 제거
- 노트/툴팁 형식 통일
- `{{version}}` 플레이스홀더 치환
- 링크, 앵커, 인라인 코드, 코드 블록 검증

## 4. 정제 작업 원칙

정제 단계에서는 문서의 의미를 바꾸지 않는다.

원칙은 다음과 같다.

1. 번역문을 임의로 다시 쓰지 않는다.
2. 정제 대상은 문서 형식, Markdown 구조, 코드/링크/이미지/노트 처리로 제한한다.
3. 코드 블록 내부의 코드는 번역하지 않는다.
4. 코드 블록 내부의 주석도 원문 영어를 유지한다.
5. 인라인 코드는 원문과 동일하게 유지한다.
6. 링크 URL과 앵커는 변경하지 않는다.
7. 문서 디자인용 스타일 코드는 제거한다.
8. 변경 여부를 추적할 수 있도록 정제 항목별 결과를 기록한다.

## 5. 번역 전 사전 정제

번역 전에 처리해야 하는 항목이다.

이미 번역이 끝난 문서라면, 다음 항목이 사전에 처리되었는지 확인하고 누락된 경우 후처리에서 보완한다.

---

### 5.1 base64 인코딩 이미지 플레이스홀더 치환

AI 토큰 사용량을 줄이고, 이미지 데이터가 번역 대상에 포함되지 않도록 base64 인코딩 이미지는 플레이스홀더로 치환한다.

#### 대상

다음과 같은 형태의 이미지 데이터:

```html
<img src="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..." />
```

또는 Markdown 이미지 안에 포함된 base64 데이터:

```md
![image](data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...)
```

#### 처리 방식

base64 전체 문자열을 플레이스홀더로 치환한다.

예:

```md
![image](data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...)
```

치환 후:

```md
![image](__BASE64_IMAGE_001__)
```

또는 HTML 이미지인 경우:

```html
<img src="__BASE64_IMAGE_001__" />
```

#### 플레이스홀더 매핑

치환 시 반드시 원본과 플레이스홀더의 매핑을 별도로 보관한다.

```md
| Placeholder | Original |
|---|---|
| `__BASE64_IMAGE_001__` | `data:image/png;base64,...` |
| `__BASE64_IMAGE_002__` | `data:image/svg+xml;base64,...` |
```

#### 번역 후 처리

번역이 완료된 뒤 플레이스홀더를 원본 base64 데이터로 복원한다.

검증 항목:

- 모든 플레이스홀더가 복원되었는가?
- base64 문자열이 손상되지 않았는가?
- 이미지 태그 구조가 유지되었는가?
- 플레이스홀더가 최종 문서에 남아 있지 않은가?

---

### 5.2 `<style>` 태그 및 페이지 디자인 코드 제거

문서 페이지 디자인에만 영향을 주는 `<style>` 태그와 CSS 코드는 제거한다.

#### 제거 대상

```html
<style>
  .collection-method {
    color: red;
  }
</style>
```

또는 문서 렌더링용 스타일 코드:

```html
<style type="text/css">
  ...
</style>
```

#### 처리 원칙

- `<style>` 시작 태그부터 `</style>` 종료 태그까지 제거한다.
- 페이지 디자인용 CSS만 제거한다.
- 코드 예제 안에 포함된 CSS 샘플은 제거하지 않는다.
- fenced code block 안의 `<style>` 예시는 문서 내용으로 보고 유지한다.

#### 제거 전

```html
<style>
  .page-title {
    margin-top: 20px;
  }
</style>

# Getting Started
```

#### 제거 후

```md
# Getting Started
```

#### 주의 사항

다음처럼 코드 블록 안에 있는 `<style>`은 제거하지 않는다.

````md
```html
<style>
  body {
    color: black;
  }
</style>
```
`````

### 6.1 들여쓰기 기반 코드 블록을 백틱 코드 블록으로 변환

원문에서 들여쓰기로 작성된 코드 블록은 Markdown fenced code block 형식으로 변환한다.

#### 변환 전

```md
다음 명령어를 실행합니다.

    npm install
    npm run build
```

#### 변환 후

````md
다음 명령어를 실행합니다.

```bash
npm install
npm run build
```
````

#### 언어 지정

가능하면 코드 종류에 따라 언어를 지정한다.

| 코드 유형      | 코드 블록 언어 |
| ---------- | -------- |
| Shell 명령어  | `bash`   |
| JavaScript | `js`     |
| TypeScript | `ts`     |
| JSON       | `json`   |
| HTML       | `html`   |
| CSS        | `css`    |
| Python     | `python` |
| YAML       | `yaml`   |
| XML        | `xml`    |
| 알 수 없음     | 생략       |

언어를 확신할 수 없으면 언어 태그를 생략한다.

````md
```
unknown code
```
````

---

### 6.2 목록의 들여쓰기를 코드 블록으로 오인하지 않기

목록 내부의 들여쓰기 문장은 코드 블록으로 변환하지 않는다.

#### 코드 블록으로 변환하면 안 되는 예

```md
- 첫 번째 항목
  - 하위 항목입니다.
  - 또 다른 하위 항목입니다.

1. 설정을 엽니다.
   1. API 키를 선택합니다.
   2. 저장을 클릭합니다.
```

위 예시는 목록 구조이므로 코드 블록으로 감싸지 않는다.

---

### 6.3 들여쓰기 코드 블록 판별 기준

다음 조건을 만족하는 경우에만 코드 블록으로 변환한다.

#### 코드 블록으로 판단할 수 있는 경우

* 4칸 이상 들여쓰기된 연속된 줄이다.
* 목록 항목의 하위 설명이 아니다.
* 코드 또는 명령어 패턴을 포함한다.
* 앞뒤 문맥상 예제 코드, 명령어, 설정값, 출력값이다.

예:

```md
다음은 설정 예시입니다.

    {
      "enabled": true,
      "timeout": 3000
    }
```

변환 후:

````md
다음은 설정 예시입니다.

```json
{
  "enabled": true,
  "timeout": 3000
}
```
````

#### 코드 블록으로 판단하지 않는 경우

* `-`, `*`, `+`, `1.` 등 목록 marker 아래의 들여쓰기 문장
* 목록 항목의 설명 문단
* 인용문 안의 들여쓰기
* 표 정렬을 위한 공백
* 단순 줄바꿈 정렬
* 한국어 설명문이 들여쓰기된 경우

예:

```md
- 옵션을 설정합니다.
    이 옵션은 기본적으로 활성화되어 있습니다.
```

위 예시는 목록 항목의 설명 문단이므로 코드 블록으로 변환하지 않는다.

---

### 6.4 base64 이미지 플레이스홀더 복원

번역 전 치환한 base64 이미지 플레이스홀더를 원본 값으로 복원한다.

#### 복원 전

```html
<img src="__BASE64_IMAGE_001__" />
```

#### 복원 후

```html
<img src="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..." />
```

#### 검증

* `__BASE64_IMAGE_` 형식의 플레이스홀더가 남아 있지 않아야 한다.
* 복원된 base64 문자열이 원본과 정확히 일치해야 한다.
* 이미지 태그의 다른 속성이 손상되지 않아야 한다.

---

### 6.5 `<img>` 태그를 self-closing 형식으로 변환

닫는 태그가 없는 HTML 이미지 태그를 self-closing 형식으로 변환한다.

#### 변환 전

```html
<img src="/images/example.png" alt="Example">
```

#### 변환 후

```html
<img src="/images/example.png" alt="Example" />
```

#### 처리 대상

```html
<img src="..." alt="...">
```

#### 처리 제외

이미 self-closing 형식인 경우 변경하지 않는다.

```html
<img src="/images/example.png" alt="Example" />
```

#### 주의 사항

다음 속성은 유지한다.

* `src`
* `alt`
* `width`
* `height`
* `class`
* `id`
* `loading`
* `data-*`

예:

```html
<img src="/img/a.png" alt="A" width="300" class="diagram">
```

변환 후:

```html
<img src="/img/a.png" alt="A" width="300" class="diagram" />
```

---

### 6.6 제목 옆 원문 스타일 클래스 제거

제목 뒤에 붙은 원문 스타일 클래스는 제거한다.

#### 대상

```md
### `after()` {.collection-method}
```

#### 결과

```md
### `after()`
```

#### 추가 예시

변환 전:

```md
## Methods {.section-title}
### `before()` {.collection-method}
#### Parameters {.params}
```

변환 후:

```md
## Methods
### `before()`
#### Parameters
```

#### 처리 규칙

* Markdown 제목 줄에서만 처리한다.
* 제목 텍스트는 변경하지 않는다.
* 인라인 코드, 링크, 앵커는 유지한다.
* `{.class-name}` 형식의 스타일 클래스만 제거한다.

#### 처리 대상 패턴

```md
# Title {.class}
## Title {.class-name}
### `method()` {.collection-method}
#### Title {.a .b}
```

#### 처리 제외

일반 본문에서 의미가 있는 중괄호 표현은 제거하지 않는다.

```md
Use `{ key: value }` to define an object.
```

### 6.7 노트 / 툴팁 형식 통일

문서 내 다양한 형태의 노트, 팁, 경고 표현을 Markdown admonition 형식으로 통일한다.

표준 형식:

```md
> [!NOTE]
> 메시지입니다.
```

---

#### 6.7.1 `{note}` 형식 변환

변환 전:

```md
> {note}
> This feature is available only in the latest version.
```

변환 후:

```md
> [!NOTE]
> 이 기능은 최신 버전에서만 사용할 수 있습니다.
```

---

#### 6.7.2 `> **Note**` 형식 변환

변환 전:

```md
> **Note**
> This setting applies only to new projects.
```

변환 후:

```md
> [!NOTE]
> 이 설정은 새 프로젝트에만 적용됩니다.
```

---

#### 6.7.3 `> Note:` 형식 변환

변환 전:

```md
> Note: This operation cannot be undone.
```

변환 후:

```md
> [!NOTE]
> 이 작업은 실행 취소할 수 없습니다.
```

---

#### 6.7.4 한 줄 노트 변환

변환 전:

```md
> **Note:** You must restart the server.
```

변환 후:

```md
> [!NOTE]
> 서버를 다시 시작해야 합니다.
```

---

#### 6.7.5 여러 줄 노트 변환

변환 전:

```md
> **Note**
> This feature requires administrator permissions.
> Contact your administrator if you cannot access it.
```

변환 후:

```md
> [!NOTE]
> 이 기능에는 관리자 권한이 필요합니다.
> 액세스할 수 없는 경우 관리자에게 문의하세요.
```

---

### 6.8 노트 유형별 표준화

가능하면 원문 의미에 따라 다음 형식으로 통일한다.

| 원문 표현                      | 표준 형식          |
| -------------------------- | -------------- |
| `Note`, `{note}`           | `[!NOTE]`      |
| `Tip`, `{tip}`             | `[!TIP]`       |
| `Warning`, `{warning}`     | `[!WARNING]`   |
| `Caution`, `{caution}`     | `[!CAUTION]`   |
| `Important`, `{important}` | `[!IMPORTANT]` |

단, 현재 문서 표준이 모두 `[!NOTE]`로 통일하는 것이라면 모든 툴팁/노트를 `[!NOTE]`로 변환한다.

이 작업의 기본 기준은 다음과 같다.

```md
> [!NOTE]
> message
```

### 6.9 `{{version}}` 플레이스홀더 치환

문서 내 `{{version}}` 플레이스홀더를 최종 문서에 적용할 버전 문자열로 치환한다.

#### 입력

```md
Install version {{version}} of the package.
```

#### 버전 문자열

```text
12.x
```

#### 출력

```md
Install version 12.x of the package.
```

또는 한국어 번역문:

```md
패키지의 12.x 버전을 설치합니다.
```

#### 처리 원칙

* 문서 전체의 `{{version}}`을 동일한 값으로 치환한다.
* 영어 주석 안의 `{{version}}`도 필요한 경우 치환한다.
* 링크 URL 안의 `{{version}}`도 치환한다.
* 코드 블록 안의 `{{version}}`도 실제 문서에서 필요한 값이면 치환한다.
* 단, 예시 코드에서 의도적으로 플레이스홀더 자체를 보여주는 경우는 유지 여부를 확인한다.

#### 검증

최종 문서에 다음 문자열이 남아 있지 않아야 한다.

```text
{{version}}
```

## 7. 정제 작업 순서

정제는 다음 순서로 진행한다.

```text
1. base64 이미지 플레이스홀더 상태 확인
2. <style> 태그 및 디자인 코드 제거 여부 확인
3. 들여쓰기 기반 코드 블록 변환
4. 목록 들여쓰기 오인 변환 여부 확인
5. <img> 태그 self-closing 변환
6. 제목 옆 스타일 클래스 제거
7. 노트 / 툴팁 형식 통일
8. {{version}} 플레이스홀더 치환
9. base64 이미지 복원
10. 최종 Markdown 구조 확인
```

권장 순서:

* base64 치환은 번역 전에 수행한다.
* base64 복원은 모든 텍스트 정제가 끝난 뒤 수행한다.
* `{{version}}` 치환은 링크 검증 전에 수행한다.
* 코드 블록 정리는 노트 변환보다 먼저 수행한다.
* 코드 블록 내부 텍스트는 이후 정제 대상에서 제외한다.

### 8.1 원문 앵커와 링크 유지 검증

#### 확인 항목

* 링크 텍스트만 번역되고 URL은 보존되었는가?
* `#anchor-name` 형식의 앵커가 손상되지 않았는가?
* `{{version}}` 치환 후 링크가 정상 형식인가?
* 링크 괄호가 깨지지 않았는가?

#### 예시

번역 후 정상:

```md
[프로젝트 생성](./projects#create-a-project)을 참조하세요.
```

번역 후 문제:

```md
[프로젝트 생성](./projects#프로젝트-생성)을 참조하세요.
```

위 예시는 원문 앵커가 번역되어 손상된 경우다.

### 8.2 인라인 코드 유지 검증

#### 검증 대상

백틱으로 감싸진 인라인 코드:

```md

`config.yaml`

```

#### 확인 항목

* 인라인 코드가 번역되지 않았는가?
* 백틱이 누락되지 않았는가?
* 코드 내부의 대소문자가 유지되었는가?
* 코드 내부의 언더스코어, 하이픈, 슬래시가 유지되었는가?
* 인라인 코드가 일반 텍스트로 풀리지 않았는가?
* 일반 텍스트가 불필요하게 인라인 코드로 바뀌지 않았는가?

#### 정상 예시

원문:

```md
Set `user_id` to the ID of the user.
```

번역:

```md
`user_id`를 사용자의 ID로 설정합니다.
```

#### 문제 예시

```md

```

위 예시는 `user_id` 인라인 코드가 번역되어 손상된 경우다.

### 8.3 코드 블록 유지 검증

#### 검증 대상

* fenced code block

#### 확인 항목

* 코드 블록 내부 주석이 영어 원문으로 유지되었는가?

* 코드 블록 언어 태그가 적절한가?

````md
// 새 클라이언트를 생성합니다

```
````

코드 블록 내부 주석은 번역하지 않는다.

## 9. 자동 검증 권장 항목

가능하면 다음 항목은 스크립트 또는 정규식으로 자동 검증한다.

---

### 9.1 남아 있으면 안 되는 문자열

```text
{{version}}
__BASE64_IMAGE_
<style
</style>
{.collection-method}
{.section-title}
> {note}
> **Note**
> Note:
```

단, 코드 블록 안에 예시로 들어간 문자열은 예외 처리한다.

---

### 9.2 확인할 패턴

#### 닫히지 않은 이미지 태그

```regex
<img\b(?![^>]*\/>)
```

#### 제목 옆 스타일 클래스

```regex
^(#{1,6}\s+.+?)\s+\{[^}]*\}\s*$
```

#### base64 플레이스홀더 잔존

```regex
__BASE64_IMAGE_\d+__
```

#### 버전 플레이스홀더 잔존

```regex
\{\{version\}\}
```

#### 기존 note 형식 잔존

```regex
^>\s*(\{note\}|\*\*Note\*\*|Note:)
```

```md
- `{{version}}` 치환 대상 버전: `12.x`
- 특정 노트가 `[!NOTE]`인지 `[!WARNING]`인지 확인 필요
- 코드 예제 안의 `<style>` 유지 여부 확인 필요

## 5. 최종 상태

최종 문서는 번역 변경분 반영, 정제, 링크/앵커/코드 검증을 완료했다.
```

## 13. 작업 요청 템플릿

정제 / 검증 작업을 요청할 때는 아래 템플릿을 사용한다.

````md
# 한국어 기술 문서 정제 / 검증 요청

## 작업 목표

번역이 완료된 한국어 기술 문서를 정제하고 검증해 주세요.

정제는 문서 의미를 바꾸지 않고 Markdown 구조, 코드, 링크, 이미지, 노트, 플레이스홀더를 정상화하는 작업입니다.

---

## 입력 자료

1. 번역 완료 한국어 문서
2. 영어 diff
3. 기존 한국어 문서
4. 적용할 버전 문자열: `{version}`

---

## 정제 규칙

1. 들여쓰기로 작성된 원문의 코드 블록을 백틱 코드 블록으로 감싸 주세요.
2. 목록의 들여쓰기를 코드 블록으로 오인하지 마세요.
3. base64 인코딩 이미지는 번역하지 말고 플레이스홀더로 치환한 뒤, 번역 후 원본으로 복원해 주세요.
4. 문서 페이지 디자인에 영향을 주는 `<style>` 태그 및 코드는 제거해 주세요.
5. 코드 예제 안의 `<style>`은 제거하지 마세요.
6. `<img>` 태그는 `<img />` 형식으로 변환해 주세요.
7. 제목 옆 원문 스타일 클래스는 제거해 주세요.
   - 예: `### 'after()' {.collection-method}` → `### 'after()'`
8. 다양한 형태의 툴팁/노트를 다음 형식으로 통일해 주세요.

```md
> [!NOTE]
> message
````

9. 문서 내 `{{version}}` 플레이스홀더를 지정된 버전 문자열로 치환해 주세요.

---

## 검증 규칙

1. 원문 앵커와 링크가 유지되었는지 확인해 주세요.
2. 인라인 코드가 유지되었는지 확인해 주세요.
3. 코드 블록 내부의 코드와 주석은 원문 영어로 유지되었는지 확인해 주세요.
4. base64 이미지가 정상 복원되었는지 확인해 주세요.
5. `<style>` 제거, `<img />` 변환, 제목 클래스 제거, 노트 형식 통일, `{{version}}` 치환이 정상 처리되었는지 확인해 주세요.
6. Markdown 구조가 깨지지 않았는지 확인해 주세요.

```
## 14. 최종 운영 기준

정제 / 검증 단계의 핵심 기준은 다음과 같다.

> 번역문은 의미 변경 없이 유지한다.
> 코드, 링크, 앵커, 이미지, 플레이스홀더는 원문 기준으로 보존한다.
> 문서 렌더링과 유지보수에 필요한 Markdown 형식만 정제한다.
> 자동 검증과 수동 검토를 함께 수행한다.

최종 산출물은 다음 조건을 만족해야 한다.

1. 영어 diff의 변경 사항이 한국어 문서에 반영되어 있다.
2. 기존 한국어 문서의 용어와 문체가 유지되어 있다.
3. 코드와 인라인 코드는 번역되지 않았다.
4. 원문 앵커와 링크는 유지되어 있다.
5. base64 이미지는 손상 없이 복원되어 있다.
6. `<style>` 태그와 디자인 코드는 제거되어 있다.
7. `<img>` 태그는 `<img />` 형식이다.
8. 제목 옆 스타일 클래스는 제거되어 있다.
9. 노트/툴팁은 표준 형식으로 통일되어 있다.
10. `{{version}}` 플레이스홀더는 지정된 버전 문자열로 치환되어 있다.
```
